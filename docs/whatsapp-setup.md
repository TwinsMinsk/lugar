# Подключение WhatsApp Business

Инструкция для владельца. Часть шагов выполняет только человек с доступом к бизнес-аккаунту Meta —
разработчик их сделать не может.

**Заложите на это несколько дней.** Верификация бизнеса у Meta и одобрение шаблонов — внешние
процедуры с непредсказуемым сроком. Сайт работает и собирает заявки без WhatsApp, поэтому запуск
можно не откладывать.

---

## Что уже работает без подключения

Режим по умолчанию — `fallback`. В нём:

- форма на сайте создаёт заявку в CRM, как обычно;
- кнопки «Написать в WhatsApp» ведут на `wa.me` — переписка идёт в вашем обычном приложении;
- в карточке заявки видно, что интеграция не подключена, а не пустая лента.

Чего в этом режиме нет: истории переписки в карточке и автоматического уведомления о новой заявке.
Заявки при этом не теряются — они в разделе «Заявки».

---

## Что понадобится

| Что | Где взять | Кто делает |
| --- | --- | --- |
| Business Portfolio с пройденной верификацией | Meta Business Suite | владелец |
| WhatsApp Business Account (WABA) | там же | владелец |
| Рабочий номер телефона | **не тот, что уже привязан к обычному WhatsApp** | владелец |
| System User и его токен | Business Settings → Users → System Users | владелец |
| App Secret | Meta for Developers → приложение → Settings → Basic | владелец |
| Verify token | придумываете сами, любая длинная случайная строка | владелец |

### Про номер

Номер, уже используемый в обычном WhatsApp или WhatsApp Business, **придётся сначала удалить оттуда**.
Один номер не может одновременно работать в приложении и в Cloud API. Если рабочий номер студии
нужен в телефоне — берите для API отдельный.

### Про токен

Нужен токен **System User**, а не обычный пользовательский. Пользовательский живёт часы и молча
перестаёт работать — уведомления просто перестанут приходить, без ошибки на сайте. У System User
токен постоянный.

Права токена: `whatsapp_business_messaging`, `whatsapp_business_management`.

## Порядок подключения

### 1. Переменные окружения

В Railway, в сервисе сайта:

```
WHATSAPP_MODE=cloud_api
WHATSAPP_PHONE_NUMBER_ID=<Phone number ID из карточки номера>
WHATSAPP_BUSINESS_ACCOUNT_ID=<WABA ID>
WHATSAPP_ACCESS_TOKEN=<токен System User>
WHATSAPP_APP_SECRET=<App Secret приложения>
WHATSAPP_WEBHOOK_VERIFY_TOKEN=<придуманная строка>
NEXT_PUBLIC_WHATSAPP_PHONE=<номер цифрами, без плюса>
```

Проверка при старте — всё или ничего: если `WHATSAPP_MODE=cloud_api`, но хотя бы одна из
`WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_APP_SECRET`,
`WHATSAPP_WEBHOOK_VERIFY_TOKEN` пуста, приложение не запустится. Это сделано намеренно: наполовину
настроенная интеграция молча роняла бы уведомления о заявках.

### 2. Webhook

В приложении Meta → WhatsApp → Configuration → Webhook:

- **Callback URL**: `https://ваш-домен/api/whatsapp/webhook`
- **Verify token**: та же строка, что в `WHATSAPP_WEBHOOK_VERIFY_TOKEN`

Нажмите Verify and Save. Если Meta говорит «The callback URL couldn't be validated» — проверьте, что
сайт уже задеплоен с новыми переменными и открывается по https.

Подпишитесь на три поля:

| Поле | Зачем |
| --- | --- |
| `messages` | входящие сообщения и статусы доставки |
| `message_template_status_update` | шаблон остановили или отклонили — иначе уведомления тихо перестанут уходить |
| `phone_number_quality_update` | Meta снизила лимит по качеству номера |

### 3. Шаблон для уведомления о заявке

Отдельная задача, и её нельзя пропустить.

Номера ваших же сотрудников **не имеют исключения** из правил Meta. Уведомление о новой заявке уходит
вне 24-часового окна, а значит требует одобренного шаблона категории **UTILITY**.

Создайте шаблон в Business Manager → WhatsApp Manager → Message Templates. Текст с четырьмя
подстановками, например:

```
Новая заявка на сайте. Имя: {{1}}. Услуга: {{2}}. Телефон: {{3}}. Номер: {{4}}
```

После одобрения:

```
WHATSAPP_LEAD_ALERT_TEMPLATE_NAME=<имя шаблона>
WHATSAPP_LEAD_ALERT_TEMPLATE_LANGUAGE=ru
WHATSAPP_INTERNAL_RECIPIENTS=<номера сотрудников через запятую, в формате +34...>
```

Пока шаблон не одобрен, уведомления не отправляются. Заявки при этом видны в разделе «Заявки», а если
настроена почта — приходит письмо.

### 4. Сервис-воркер

Отправкой занимается отдельный процесс, не сайт. В Railway создайте **второй сервис** из того же
репозитория:

- команда запуска: `npm run worker`
- те же переменные окружения, включая `DATABASE_URL`

Без него сообщения будут копиться в очереди и не уходить. Это не cron: у Railway cron минимальный
интервал пять минут, а горячая заявка столько ждать не должна.

---

## Правило 24 часов

Свободный текст можно отправлять только в течение 24 часов после **последнего сообщения клиента**.
Это правило Meta, обойти его нельзя.

В карточке заявки это видно прямо: пока окно открыто, есть поле для ответа; когда закрылось — вместо
поля появляется выбор одобренного шаблона и ссылка, чтобы ответить со своего телефона.

Окно проверяется трижды — при отрисовке страницы, при нажатии «Отправить» и воркером перед самой
отправкой. Оно может закрыться, пока сообщение набирают.

---

## Проверка, что всё работает

1. Напишите на рабочий номер с личного телефона.
2. Откройте заявку этого номера в панели — сообщение должно появиться в разделе WhatsApp, а метка
   смениться на «окно 24 ч открыто».
3. Ответьте из панели. Сообщение уходит в очередь, воркер отправляет его в течение нескольких секунд.

Если сообщение не появилось: проверьте в приложении Meta → Webhooks, что доставки идут и не
накапливаются ошибки.

## Что может пойти не так

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Meta не проходит верификацию webhook | сайт не задеплоен с новым verify token, или адрес не https | задеплойте и повторите |
| Уведомления о заявках не приходят | шаблон не одобрен, остановлен или не задан | проверьте статус шаблона в WhatsApp Manager |
| Сообщения копятся в очереди | воркер не запущен или упал | проверьте логи сервиса воркера в Railway |
| Ответ не отправляется, статус «вне окна» | прошло больше 24 часов | отправьте шаблон или ответьте с телефона |
| Всё внезапно перестало работать | истёк или отозван токен | перевыпустите токен System User |

Сообщение, не доставленное после всех попыток, попадает в «не доставлено» на карточке заявки.
Владелец может отправить его повторно кнопкой «Повторить» — но сначала стоит устранить причину,
иначе оно снова упадёт.

---

## Чего система не делает намеренно

- **Не использует неофициальную автоматизацию WhatsApp и не подключается к WhatsApp Web.** Это
  нарушение правил Meta и повод для блокировки номера.
- **Не гарантирует ровно однократную доставку.** Если соединение оборвалось между отправкой запроса и
  получением ответа, сообщение могло уйти, а мы об этом не узнали. Для внутренних уведомлений дубль
  безвреден. Для клиентских шаблонов такая попытка помечается и требует человека.
- **Не объединяет обращения одного человека автоматически.** Повторная заявка помечается как
  возможный дубль, решение остаётся за вами.
